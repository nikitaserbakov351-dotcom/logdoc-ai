# LogDoc AI — RAG-ассистент по документам

![Python](https://img.shields.io/badge/Python-3.11+-3776AB?logo=python&logoColor=white)
![pypdf](https://img.shields.io/badge/pypdf-PDF%20ingest-EF2C5E)
![offline-first](https://img.shields.io/badge/offline--first-extractive%20mode-10B981)
![Tests](https://github.com/nikitaserbakov351-dotcom/logdoc-ai/actions/workflows/tests.yml/badge.svg)

Ассистент вопрос-ответ по корпоративным документам (накладные, договоры, акты): загрузите PDF или текстовые файлы — задавайте вопросы и получайте ответы **со ссылками на конкретные файлы и страницы**. Проект реализует полный RAG-пайплайн (ingest → чанкинг → индексация → retrieval → генерация) и намеренно начинается с оффлайн-режима: поиск с цитатами работает без нейросетей и без отправки документов во внешние сервисы — приватность встроена в архитектуру, а не прикручена потом.

## Ключевые возможности

- **Индексация документов** — PDF (через pypdf), TXT и MD; текст извлекается постранично, страницы сохраняются для цитирования.
- **Чанкинг с перекрытием** — разбиение на фрагменты заданного размера без разрыва слов; перекрытие сохраняет смысл на стыках.
- **Оффлайн-поиск с цитатами (extractive-режим)** — косинусный поиск по векторному индексу; ответ = наиболее релевантные фрагменты с точными ссылками `[1] файл, стр. N`. Ноль нейросетей, ноль сетевых вызовов, ноль галлюцинаций.
- **Генеративный режим (опционально)** — найденные фрагменты передаются в Google Gemini как контекст; модель отвечает со ссылками на источники и инструкцией «не выдумывать».
- **Два уровня эмбеддингов** — по умолчанию детерминированный hashing-эмбеддер на чистом Python (zero-dependency фолбэк); при установке `sentence-transformers` включается семантический поиск на локальной модели.

## Архитектура

```
PDF/TXT/MD ──ingest──> страницы ──chunking──> фрагменты ──embed──> векторный индекс
                                                                        │
вопрос ────────────────embed──> косинусный поиск top-k ─────────────────┘
                                        │
                          extractive (оффлайн): цитаты как есть
                          gemini (опционально): ответ LLM + источники
```

## Быстрый старт

```bash
git clone https://github.com/nikitaserbakov351-dotcom/logdoc-ai.git
cd logdoc-ai

python -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -r requirements.txt

# индексируем документы-примеры и спрашиваем
python -m logdoc.cli ingest ./samples
python -m logdoc.cli ask "кто подписал акт приёмки по заявке 152?" -k 2
```

Пример вывода:

```
[1] akt_152a.txt, стр. 1 — «АКТ ПРИЁМКИ ГРУЗА № 152-А …»

Источники:
  [1] akt_152a.txt, стр. 1 (score 0.3601)
```

Для генеративного режима добавьте ключ в `.env` (`GEMINI_API_KEY=...`) и запустите с `--backend gemini`.

Для семантического поиска вместо hashing-фолбэка: `pip install sentence-transformers` — модель (по умолчанию компактная `cointegrated/rubert-tiny2`, ~120 МБ) работает локально.

## Запуск тестов

```bash
pip install -r requirements-dev.txt
pytest -v
```

21 тест покрывает чанкинг (границы, перекрытие, целостность слов), векторное хранилище (детерминизм, релевантность, персистентность), извлечение текста (включая PDF без текстового слоя) и формирование ответов. Тесты не требуют нейросетей и выполняются за доли секунды.

## Особенности реализации

**Оффлайн-first.** Extractive-режим — не «заглушка до появления LLM», а самостоятельный инструмент: для вопросов «где это написано» точная цитата полезнее генерации, и у неё нет риска галлюцинаций.

**Hashing-эмбеддер.** Слова и символьные n-граммы хэшируются в вектор фиксированной размерности (hashing trick) — это делает поиск детерминированным, бесплатным и полностью локальным. Слабость подхода (нет синонимии) компенсируется опциональным переходом на локальные sentence-transformers, архитектура позволяет подменить эмбеддер одной строкой.

**Приватность.** Базовый сценарий не отправляет документы никуда: извлечение, индексация и поиск — локальные. Внешний вызов происходит только в явно включённом режиме `--backend gemini`, и даже тогда наружу уходят только найденные фрагменты.

## Структура проекта

```
├── logdoc/
│   ├── ingest.py      # извлечение текста по страницам (pypdf, txt, md)
│   ├── chunking.py    # перекрывающиеся фрагменты с сохранением страниц
│   ├── store.py       # эмбеддеры (hashing + sentence-transformers), поиск, персистентность
│   ├── answer.py      # extractive-ответ и генеративный режим Gemini
│   └── cli.py         # команды: ingest, ask
├── samples/           # демо-документы (накладная, договор, акт)
├── tests/             # 21 pytest-тест
├── .github/workflows/tests.yml
└── requirements.txt   # (+ requirements-dev.txt для тестов)
```
